Getting started

Documentation home · User guide

This page takes you from the demo project to a package for your vCenter. Part A takes 5 minutes and changes nothing. Part B uses your inventory. Part C runs the package on a lab vCenter.

Part A: learn with the demo project

  1. Unpack the package to a local folder or a file share. Open planner\vds-planner.html in Microsoft Edge.
  2. On the start screen, select Try the demo project. The demo has four made-up clusters. Nothing is written until you save.
  3. Look at the guide bar at the top. It shows the steps from the inventory to the package, and the line Next tells you what to do.
  4. Select the tab Demo draft. Each box is one new VDS, drawn like the switch view of the vSphere Client: port groups on the left, uplinks on the right.
  5. Select a port group. Its settings show on the right, and the Uplinks box shows its active and standby uplinks. Change the VLAN or the teaming and see the checks change at the bottom.
  6. Read the checks. The demo has blocking items on purpose: a host with an earlier ESXi version, a VDS with one uplink, a port group that is not on all hosts. The rules reference tells what each item means.
  7. Select Help, Guided tour for a tour of the screen. Put the mouse pointer on a button for a short help bubble.

Part B: plan your vCenter

  1. Get the inventory of the vCenter: the inventory workbook (.xlsx), or run scripts\inventory\Export-VssLayout.ps1 for each cluster. The user guide lists the sheets that the planner uses.
  2. Select File, New project, then Import inventory (Ctrl+I). Select the workbook or the CSV files. The planner shows the sheets that it found and the notes about missing sheets.
  3. Enter the site name and select Make the project. The project gets two drafts: one keeps the port group names, one has names that vCenter accepts in a datacenter.
  4. Select Save the project file. Keep the project file in your environment, not in a public place: it holds the inventory of your vCenter.
  5. In the inventory column, set the security zone of each cluster. The planner uses the zone for the rule about a VDS for more clusters.
  6. Open a draft. Correct the blocking checks: confirm the VLAN trunk with the network team (V-05), fix names, set the ephemeral port group for the vCenter VM, add VMkernel adapters if necessary.
  7. To put more clusters on one VDS, drag the switch of a cluster from the inventory onto the VDS. The planner shows the differences, and you accept them.
  8. Select File, Project settings. Enter the vCenter, the toolkit folder on the jump host and the vCenter user.
  9. When the guide bar shows no blocking check, select Commit. Enter your name, select a folder, and the planner writes four files: the plan, its hash, the launcher and the report. Then save the project again.

Part C: run the package on a lab vCenter

  1. Copy the toolkit folder and the four package files to the jump host. Install PowerCLI 13 or later if necessary: 
    Install-Module VMware.PowerCLI -Scope CurrentUser
  2. Open PowerShell in the package folder. If Windows blocks the copied files, follow the script policy of your organization, for example: 
    Get-ChildItem -Filter *.ps1 | Unblock-File
  3. Run the read-only check. It asks for the password of the vCenter user and prints READY or NOT READY: 
    .\Invoke-<draft>-v1.ps1 -Part Check
  4. Run a rehearsal. It shows each change and makes none: 
    .\Invoke-<draft>-v1.ps1 -WhatIf
  5. In the change window, run it with no -WhatIf. Then move the hosts and the VMs one at a time with Move-HostToVds.ps1 and Move-VmNetworkToVds.ps1, as the report of the package shows.
Before production. Do the live test checklist on a lab vCenter and on one pilot cluster. Keep the transcripts and CSV logs of the output folder with the change record.
