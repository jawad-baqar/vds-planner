Design rules and checks

Documentation home · User guide, checks

The planner checks each draft against the design rules all the time. The checks show at the bottom of the draft and in the guide bar. Each line names the VDS, the rule and the action.

LevelMeaning
blockThe commit is not possible. Correct the item first.
warnThe commit is possible. Read the item and make sure that it is correct for your environment.
infoA note for the change window, for example the VMkernel adapters that move later.

The design rules

RuleRule textWhat the planner doesWhen it blocks, do this
V-01One VDS for each standard switch of each cluster. vSwitch0 becomes <cluster>-vds01, the next switch <cluster>-vds02.Add and Add all switches make one VDS for each switch with this name, with the port groups and the uplinks of the switch.No block. Rename the VDS if your naming standard is different.
V-02The VDS has two uplinks or more.Counts the uplinks of the standard switch in the inventory.Add a second physical adapter to the standard switch of the hosts, import the inventory again and select Sync from inventory.
V-05A port group that is not on all hosts is made only after a VLAN trunk check.Marks the port groups that are on fewer hosts than the switch, or on fewer clusters than the VDS.Ask the network team to confirm that the physical switch ports of all hosts carry the VLAN. Then select the VDS name and the trunk check for all port groups of the VDS, or the check on one port group.
V-06The uplink layout of most hosts is the standard.Uses the layout of most hosts (on a tie, the first host) and lists the hosts with a different layout.No block (warning). Correct the hosts with a different layout before the migration.
V-07A switch on a minority of hosts with no uplinks is not converted.Leaves the switch out of the plan.No block.
V-08One VDS for more than one cluster only in one datacenter and one security zone. DMZ and internal clusters never share a VDS.Blocks a different datacenter, a different or missing zone and a cluster with fewer than two uplinks. Shows the other differences (uplink names, NIC speed, port groups): you accept them, and the plan records them.Set the zone of each cluster. Move the cluster to another VDS, or select Accept the differences on the VDS.
V-09Design defaults: VDS version 8.0.3, MTU 1500, LLDP in both directions, teaming route based on originating virtual port, an ephemeral port group for the vCenter VM.Uses the defaults for each new VDS. A new vMotion or Provisioning adapter sets MTU 9000 (you can change it).No block. Add an ephemeral port group on the VDS of the cluster that runs the vCenter VM.
V-10The iDRAC USB switch and the BMC switch (vSwitchiDRACvusb, vSwitchBMC) are removed, not converted.Leaves these switches out of the plan.No block.

Two more design principles have no check of their own: the VDS uses the physical uplinks of the standard switch, and it gets only the port groups of its own clusters.

Checks of the scripts

Invoke-VdsPlan.ps1 and Get-VdsPlanPreflight.ps1 do the same checks again against the live vCenter before any change: the hash of the plan file, the format, the hosts and their versions, the port group names in the datacenter and the IP addresses in use. A blocking item stops the script before it changes anything.
