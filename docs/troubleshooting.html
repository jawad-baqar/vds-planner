Troubleshooting and questions

The planner

Save downloads a file. The recent project list is empty.

Save to the same file and the recent list use the file access feature of Microsoft Edge and Google Chrome. Other browsers download the project file. Use Edge or Chrome.

A recent project does not open.

The file was moved, renamed or deleted, or the browser asks for access again. Select the project again with File, Open project. Remove the old line with Remove from list on the start screen.

The planner offers to restore work at the start.

The browser closed with changes that were not saved. Select Restore to open the recovery copy, then save the project. Select Discard to delete the copy.

Commit is not possible.

The draft has blocking checks. The Commit button shows their number. Select it, or Draft, Go to the checks. The rules reference tells what to do for each check.

The import says that a sheet is missing.

The planner needs the vPort sheet. The other sheets add information: without vNIC the uplinks are not known and rule V-02 blocks, without vHost the ESXi version check is not possible. Export the missing sheets and import all files together.

The import says that the input is from more than one vCenter.

A project is for one vCenter. Import the files of one vCenter. Make one project for each vCenter.

Ctrl+N or Ctrl+W does not do what I expect.

These keys belong to the browser. Use Ctrl+Alt+N for a new project and File, Close project.

Where does the planner keep my data?

In your project file. The browser storage of your computer keeps only the recent project list, the preferences and a recovery copy. The planner sends nothing over the network.

The scripts

"The file is not digitally signed" or "running scripts is disabled".

Windows blocks files that come from a browser or a file share. Follow the script policy of your organization. To unblock the files of the package:

Get-ChildItem -Filter *.ps1 | Unblock-File
"Invoke-VdsPlan.ps1 is not in the toolkit folder".

The launcher looks for the toolkit in the folder of Project settings. Run it with the correct folder:

.\Invoke-<draft>-v1.ps1 -ToolkitPath 'D:\Tools\vds-toolkit' -Part Check
"The plan file changed after the commit".

The SHA-256 hash of the plan file is not the hash of the commit. Do not use the file. In the planner, select Generate again next to the version to write the files again.

A PowerCLI command is not found.

Install PowerCLI 13 or later, with the VDS module:

Install-Module VMware.PowerCLI -Scope CurrentUser
Where are the logs?

In the output folder of the toolkit: a transcript and a CSV log for each run. Keep them with the change record.

How do I go back on a pilot cluster?

Remove-VdsPlanSwitch.ps1 removes a VDS of the plan when no host and no VM uses it. Move the uplinks and the VMkernel adapters back to the standard switch first. The user guide has the steps.
